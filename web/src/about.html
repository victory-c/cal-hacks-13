What Bullwark does

Most agent memory is one shared store and a polite prompt.
Bullwark draws the wall before retrieval.

Regulated teams run on information barriers. AI erodes them quietly: chats, saved memories and long-running agents carry context from one desk to the next. The usual answer gives the model every secret and asks it to keep them. Bullwark limits what the model can ever see.

State of the art, by design

Six ideas that make it work.
Few memory layers have any of them.

  1. 01

    Scope before retrieval

    A memory is a fixed list of fact IDs. Search runs inside that list and never sees the rest.

  2. 02

    Living scopes

    Every new fact is judged against each person's original rule and joins only the scopes it fits.

  3. 03

    Creator-bounded agents

    An agent's scope is intersected with its creator's at build, on every update and on every read.

  4. 04

    Restart on narrowing

    When access shrinks, the agent's working folder is discarded and rebuilt, not just its process stopped.

  5. 05

    Write-time quarantine

    Text that carries instructions aimed at an AI is held out of every scope before anyone can retrieve it.

  6. 06

    Memory that doesn't echo

    Context injected into a prompt is never captured back as new memory, so facts don't multiply.

1.0 — Capture

Every conversation becomes
sourced, living memory

Coding sessions, memos, chats and agent notes are distilled into short facts. Each fact keeps its source, author and history, and is filed into exactly one group.

1.1Capture where people already work

A Claude Code hook files each session as it ends. The MCP tool canon_save, an ingest API and an Add item box cover everything else. One token per person ties every capture to its author.

1.2Claude writes the facts

Claude turns a raw session into short, sourced statements. It drops rumors it can't source and never restates memory the assistant was given as if it were new.

1.3Jev triages every draft

One batched call answers three questions: keep it, which group it belongs to, and whether it contains instructions aimed at an AI. Unplaceable facts go to a moderators-only inbox.

1.4Nothing is lost, nothing duplicates

Raw sessions stay in a cold archive. Durable receipts recover sessions that ended during an outage. Exact repeats are no-ops, and a stale position is retired when its author updates it.

2.0 — Scope

Access is decided once,
in code first

Compliance describes each person's task in plain words and names what to leave out. Bullwark turns that into a fixed memory, and keeps it current as the firm learns.

2.1Exclusions run in code

Excluded groups and labels leave the pool before any model sees a single fact. Relevance can never bring them back.

2.2Moss finds, Jev decides

Moss hybrid retrieval proposes candidates from what remains. Jev answers yes or no in one batched call, and code applies the threshold. A "maybe" on an exclusion counts as yes.

2.3Scopes that stay alive

Each new fact is checked against every person's original rule and joins the scopes it fits, within seconds of being written.

2.4Only moderators move the wall

Only Compliance adds people, edits rules or changes tiers. Models never grant access.

3.0 — Agents

Agents inherit a scope.
They never exceed it.

Anyone can create an agent and give it work. It runs in its own sandbox, holding only the facts its scope allows, and its findings flow back into its creator's memory.

3.1Sandboxed by construction

Each run gets its own folder holding only its scope's facts as markdown. File tools are confined to that folder in code. There is no shell and no network, and it can write only to out/.

3.2Bounded by its creator

Creating an agent never creates a route to more facts. Ben cannot hand his agent anything he was never given.

3.3Restart on narrowing

When a fact leaves the scope mid-run, the step is interrupted, the folder and its drafts are thrown away, and the agent restarts from what it may still see.

3.4Findings flow back to memory

Notes an agent saves become facts in its creator's memory. A save that cites a fact the agent has lost is refused.

4.0 — Trust

No refusals. No hints.
A record of everything sent.

People never hit a wall they can see. Compliance sees exactly which facts every person and agent received, and why.

4.1Invisible by design

Nothing outside a scope is counted, named or hinted at. canon_whoami shows a person their task, never their exclusions.

4.2Uncertainty means exclude

An uncertain exclusion counts as yes. A fact the judge can't place waits in the moderators' inbox.

4.3Every handoff audited

The audit records the exact fact IDs each person or agent was sent. It persists across restarts and powers the handoff inspector.

4.4Measured against attacks

A finance benchmark of 60 attacks across six styles, including agent escalation and planted instructions, plus 30 legitimate tasks, compares Bullwark with no memory and with shared memory.

MossFast retrieval, inside the boundaryScope · Retrieve
  1. Sourced fact storeSessions and documents become cited facts
  2. Code-enforced scopeAllowlisted fact IDs only; excluded groups leave first
  3. Moss hybrid searchMeaning plus exact terms ranks the in-scope candidates
  4. Verify IDsCode checks every result against canonical fact IDs
  5. Context handed overSmall, cited, shaped to the task

Moss ranks candidates. Bullwark enforces access.

Why not the alternatives

  • Whole-history promptsToken-heavy, noisy context that raises cost and hallucination.
  • Keyword-only searchMisses paraphrases and intent, so context comes back incomplete.
  • Remote vector databaseMore infrastructure, extra network hops, one more system to secure.

What Moss unlocks

  • A local session indexRuns inside the Canon server; the markdown fact files stay the source of truth.
  • Hybrid search: meaning + exact termsFinds facts phrased differently, while tickers and names still match exactly.
  • Lookup for live agentsIn-session memory without standing up a second datastore.

verifiedLive Moss retrieval passed on the shared preview. The keyword retriever is a labelled simulated stand-in. We make no latency claim for Moss.

Why not the alternatives

  • One-off chat promptsNot repeatable, and structure is hard to enforce.
  • Manual fact extractionSlow, easy to miss context, and stale by the next meeting.
  • Unrestricted general agentsBroad file and tool access is a poor fit for regulated work.

What Droid enables

  • Programmatic, headless extractionRaw sessions become structured drafts with sources, with tools switched off.
  • Repeatable agent runs from the CLIStructured output, tool controls and a live step stream.
  • Fits Bullwark's sandboxesEach run sees only its folder of in-scope facts.

verifiedDroid SDK extraction runs on the shared preview. A real Droid CLI finance-agent run completed two steps under macOS Seatbelt and saved its note in 35.3 s (single run). Preview agents run on Claude, because Droid isolation on Linux is unverified.

Why not the alternatives

  • Free-text LLM judgesSlow, need parsing, and can be argued into a different answer.
  • One call per factA round trip for every candidate on every scope build.
  • Letting the model hold everythingAccess becomes a prompt instead of a boundary.

What Jev unlocks

  • Judgment on every write and buildFast enough to check each new fact against every scope.
  • One interface, four jobsTriage, admission, relevance and injection flags.
  • A safe fallbackClaude sits behind the same judge() interface if Jev is unavailable.
