# Sponsor accounts and the team preview

## Which sponsor to use for hosting

Use a small **Vultr Cloud Compute VM** if the MLH credit is available to your account.
The [live Cal Hacks Devpost](https://cal-hacks-13-0.devpost.com/) lists Best Use of Vultr;
the [official MLH offer](https://discover.vultr.com/mlh) advertises cloud credit. Verify the
actual credit, expiry, billing requirement and instance price in your account before provisioning.
The public offer does not establish this team's balance or spending authorization.

**Microsoft Azure** is the other good sponsor option. [Azure for Students](https://learn.microsoft.com/en-us/azure/education-hub/about-azure-for-students)
offers eligible students $100 for a year without a credit card. This is a general student offer,
not a confirmed event-specific grant. The same Docker setup below runs on an Azure Linux VM.
The Azure CLI is installed locally but was not signed in when checked.

Review of the supplied 26-page hacker guide and [live starter packs](https://hive.hackberkeley.org/resources):

## Credential checklist

| Local variable | Where to obtain it | Current code |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | [Claude Console API keys](https://platform.claude.com/settings/keys); verify API credit/billing there | Required for real extraction and judging. One key supplies both. |
| `FACTORY_API_KEY` | [Factory API keys](https://app.factory.ai/settings/api-keys); [official CLI reference](https://github.com/Factory-AI/factory/blob/main/docs/reference/cli-reference.mdx) | Collect for the Droid integration. The current adapter throws pending implementation. |
| `JEV_API_KEY`, `JEV_API_URL` | [TypeSafe quickstart](https://docs.typesafe.ai/introduction/quickstart), which links its console | Collect key and exact endpoint together. Our request/response adapter is still marked unverified; use Claude meanwhile. |
| `MOSS_PROJECT_ID`, `MOSS_PROJECT_KEY` | [Moss](https://moss.dev), linked from the [official SDK repo](https://github.com/usemoss/moss); [docs](https://docs.moss.dev/docs) | Collect project credentials. The current adapter throws pending implementation. |
| `CANON_CLIENT_TOKENS`, `CANON_TOKEN_DISTILLER`, `CANON_TOKEN_CLAUDE_CODE` | Generated by `npm run preview:setup` | App authentication; not sponsor API keys. Each client gets a different random token. |
| `PREVIEW_PASSWORD`, `PREVIEW_PASSWORD_HASH` | Generated by `npm run preview:setup` | Shared browser login: username `team`. Share the password directly with teammates. |

Store values only in the local `.env.preview` and the chosen server's secret file. Do not paste
them into chat, commit them, or put provider keys in the browser. `npm run preview:check` prints
presence only; it does not claim keys are valid or make paid API calls.

## Local rehearsal

Requires Node 22+, Docker and Docker Compose. Commands run from the repository root:

```bash
npm ci
npm run preview:setup
# Edit .env.preview locally and fill ANTHROPIC_API_KEY.
npm run preview:check
docker compose --env-file .env.preview -f compose.preview.yaml up -d --build --wait
```

Open `http://localhost:8080`, sign in as `team` with `PREVIEW_PASSWORD` from your local file.
These defaults bind only to loopback. To rehearse without a model key, explicitly set
`PREVIEW_ALLOW_SIMULATED=1`; the launcher then uses the heuristic distiller and fake judge and
labels the mode. Set it back to `0` for the real preview.

The launcher pins the implemented Claude adapters and disables Moss selection, even if you
have collected the future sponsor credentials. This avoids accidentally selecting unfinished
adapters. Integration work should remove those pins once it has been tested.

## Deploy on a sponsor VM

1. Activate the selected cloud offer and review the credited balance and VM cost. Account
   creation, terms acceptance, payment details, and a spending limit need the account owner's input.
2. Provision a Linux VM with Docker Compose and enough memory for the Node build (2 GB is a
   reasonable starting size). Use one instance: the current store is local files, not shared storage.
3. Point a domain/subdomain you control at the VM. Allow inbound TCP 80/443 and SSH restricted to
   the team's admin access. Do not expose 4100, 4200 or the Docker daemon.
4. Clone this repository and the branch containing this setup onto the VM. Run `npm run preview:setup`
   there if Node is installed, or transfer the generated `.env.preview` securely, preserving mode 600.
   Do not share the host's full secret file with browser viewers.
5. In that server's `.env.preview`, fill the actual Anthropic key and change:

   ```dotenv
   PREVIEW_SITE=preview.your-domain.example
   PREVIEW_PUBLIC_URL=https://preview.your-domain.example
   PREVIEW_BIND_ADDRESS=0.0.0.0
   PREVIEW_HTTP_PORT=80
   PREVIEW_HTTPS_PORT=443
   PREVIEW_ALLOW_SIMULATED=0
   ```

6. Start with the Compose command above. Caddy obtains HTTPS certificates for the configured
   domain and protects the dashboard, events and tokenless reads with the team login. Machine
   clients send their own Canon bearer token to `/api/*` or `/mcp`; the API enforces its existing
   folder grants. CORS preflight carries no data and is allowed through to the API.
7. Check the authenticated `/health`, capture a fresh test session, confirm distiller output and
   the dashboard event feed, then restart and confirm facts remain. Set capture clients' `CANON_URL`
   to the public HTTPS URL and give each its corresponding client token. The browser extension's
   host permissions must also include your chosen domain before remote capture can work.

```bash
# Check health and logs; logs must never contain the secret file.
docker compose --env-file .env.preview -f compose.preview.yaml ps
docker compose --env-file .env.preview -f compose.preview.yaml logs --tail 60
# Deploy a later commit from the shared preview branch:
git pull --ff-only
docker compose --env-file .env.preview -f compose.preview.yaml up -d --build --wait
# Stop, preserving the saved facts and certificates:
docker compose --env-file .env.preview -f compose.preview.yaml down
```

The `canon-data` volume preserves sessions and facts across restarts/rebuilds; Caddy's volumes
preserve certificates. Keep the same Compose project name across deployments and back up the data
volume before replacing the VM. Do not use `down --volumes` on the shared preview.

This deploys the implemented checkout, which still has v1 folder grants. The v2 finance walls,
entitlements and compliance flow in the PRD are not implemented by adding keys or deploying it.
Use synthetic demo data while that work continues. Teammates still edit code through Git branches;
the preview gives everyone the same running app and data.
