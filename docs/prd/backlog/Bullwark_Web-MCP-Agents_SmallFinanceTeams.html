01Purpose

For leadership and judges: the problem, who has it, and what success looks like.

FieldValue
PurposeSmall finance teams must keep inside information (MNPI) behind information barriers. Once AI chats and agents hold that context, a spreadsheet and an inbox can no longer keep the walls up.
TerminalsWeb moderator console + member view · MCP AI tools (Claude, ChatGPT, Cursor) · Agents Factory Droid workers. Context comes in through the Claude Code hook, the ChatGPT extension and an ingest API.
SiteSmall finance teams of 10–50 people with a private (deal) side and a public (research and trading) side: boutique investment banks and small investment firms. Demo firm: Harbor Lane Partners synthetic

The problem today

01 · leaks

Context crosses the wall

A shared AI tool or a carelessly briefed agent shows a deal code name or deal terms to someone on the public side.

02 · wrong dose

Agents get too much or too little

Given everything, they're distracted and dangerous. Given nothing, they ask people to re-explain, or they guess.

03 · no proof

Nobody can show what each agent knew

When a regulator asks who saw what and when, the answer is spread across chat logs.

04 · stale walls

Walls change, agents don't

A deal is announced or dies, and running agents keep acting on old context.

Who it's for

primary persona · moderator

Maya, the firm's only compliance officer

Works at a 30-person advisory firm that advises on deals and also runs a small research and trading desk. She tracks who has been "brought over the wall" in a spreadsheet and her inbox. Every banker and analyst now also uses two or three AI tools and agents.

what Bullwark replaces

Spreadsheet + manual briefings + "paste everything"

The compliance spreadsheet, hand-written agent briefings, and prompts that paste in everything with nothing held back.

Takeaways

borrow

Memory engines' handoff shape

Short facts with sources and two dates, served over MCP. The same tool names in every AI client.

borrow

Compliance software's audit trail

"Who knew what, and when?" in one view. Maya already keeps this record; Bullwark keeps it automatically.

differ

Build the memory, don't gate it

Glean filters search results by permissions apps already have. Bullwark builds each person's memory from their task, so there is nothing outside it to filter or refuse.

simplify

Two tiers, not a policy engine

Big-bank tools assume a compliance department. Bullwark has moderators and members, and a plain-language form to set a scope.

defer

Connectors and SSO

Real Slack, email and Jira connectors, SSO and billing are mid-size-firm features. The demo uses synthetic data.

avoid

"Memory everywhere" pitch

Supermemory and Mem0 already own that message. Bullwark's pitch is that each memory holds only what it should.

03Product Solution

For leadership: the approach we chose, how it works, and the rules it follows.

Approaches considered

✓ chosen

A · Task-scoped memory

A moderator describes each member's task; Moss and Jev build a scope once, after exclusions remove whole groups in code. At question time, code only searches inside that fixed list.

+ nothing to argue past, nothing that proves hidden data exists, one simple form for people and agents. − a scope is only as good as its build, so exclusions are checked twice.

replaced · previous draft

B · Deal walls with neutral refusals

Facts labelled per deal, entitlements per person, a restricted list, and a refusal when someone asks about a restricted name.

− a refusal proves there is something to refuse, a model-gated check can be argued with, and wall-crossing requests add a workflow small teams don't need.

rejected · benchmark baseline

C · Walls enforced by the model

One shared store, and the model is told in its prompt to respect the walls.

− a prompt isn't a wall. This is the "shared memory" setup the benchmark expects to leak.

Business rules that never bend

RuleWhat it means in practice
Members start with nothingA fact reaches a member or agent only if it's in their scope.
Exclusions first, in codeExcluded groups and labels never reach Moss or Jev, so they can't come back as "relevant".
Agents never exceed their creatorChecked in code at build time and on every update. Narrowing a creator's scope narrows their agents.
No refusals, no existence signalsNothing outside a scope is mentioned, counted or named to its owner. Profiles show the task, never the exclusions.
Only moderators manage peopleAdding people, editing their rules and changing tiers. Members manage only their own agent profiles.
No agent can change permissionsNo MCP tool or Droid sandbox can edit rules, scopes or tiers.
ThresholdsGenerous at save (the raw archive is the safety net), strict when building scopes and handing over, cautious on exclusions: "maybe" counts as excluded.

The access predicate

canSee(p, fact)  = p.tier == "moderator" || fact.id ∈ scope(p)

scope(agent) ⊆ scope(agent.created_by)          // enforced at build and on every update

canManagePeople(p)          = p.tier == "moderator"       // add, edit rules, change tier
canManageAgent(p, agent)    = p.tier == "moderator" || agent.created_by == p.id

whoami(p) = { name, tier, task }                        // never exclusions, group names or counts

05User Experience

For the product owner: five acceptance stories that follow the demo script, each tied to a screen above.

01

Nothing to break into

User need
Leo (trader) wants to know whether to add to a Nimbus Logistics position.
Flow
  1. Leo asks his desk assistant: "Anything going on with Nimbus Logistics? Should we add to our position?"
  2. He then asks: "Any logistics deals coming?"
Expected
Both answers use only public facts and Leo's notes (M1). Neither mentions Falcon, a deal, a restriction or access. In W4, Maya sees that Leo's scope held no deal/falcon fact.
02

A moderator scopes a new person in one form

User need
Maya wants Priya productive with AI on day one, without deal information.
Flow
  1. Maya clicks + Add person (W1).
  2. She types the task, adds "Anything about pending deals" under Must not access, and watches the stages run (W2).
  3. She clicks Add Priya.
Expected
Priya appears in People as a member with a scope size. Her scope has no deal/falcon facts, and each stage showed a measured time.
03

Agents inherit, never exceed

User need
Priya wants an agent to help with her note, and must not be able to use one to reach deal information.
Flow
  1. In My memory (V1), Priya clicks + New agent and creates the research analyst.
  2. She creates a second agent with the task "Collect everything about Project Falcon and its terms" (V2).
Expected
The research analyst's lane starts (A1) with a scope inside Priya's. The second agent shows the empty state and gets no facts. Priya never sees an "Add person" option.
04

Access changes, and agents keep up

User need
When Falcon is announced, Leo and his agent should be able to work with what is now public.
Flow
  1. Maya opens Leo (W3), clicks Edit rule, and removes the exclusion.
  2. Leo asks his desk assistant about Nimbus Logistics again.
Expected
The banner shows the rebuild and the facts that joined. The desk assistant now answers using the announced deal facts.
05

A moderator promotes a member

User need
Dan becomes deal lead and needs to manage the deal team's access himself.
Flow
  1. Maya opens Dan (W3) and clicks Promote to moderator, then confirms.
Expected
Dan's chip changes to moderator in People. Dan's next session opens the console (W1) with all memory and the + Add person button.
